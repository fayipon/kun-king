# 登入 Toast 與登入後 Header

- 狀態：已完成本地實作與驗證；使用者已明確指示「開始」。
- 需求：登入按鈕觸發toast；登入後頂部顯示balance、bell tips與menu icon。
- 現況：Auth尚無登入API，FrontendLayout Header固定顯示Log In／Register。

## 預計實作

1. 共用toast：固定於視窗右上角安全區，深色底、青綠成功圖示、關閉按鈕。多則依觸發順序由上往下排列，新通知加入最下方，不取代既有通知；各自約4秒後消失，滑鼠停留／鍵盤聚焦時暫停該則計時。逐則關閉後其餘補位，減少動態時不位移。跨路由保留訊息，以status播報。窄螢幕保留左右邊距；過多通知時限制容器高度並允許捲動。
2. 登入欄位不完整：保留現有欄位錯誤與首錯焦點，補上「Please check your login details.」toast。
3. 欄位通過：建立本次頁面的示範登入狀態，導向/frontend；顯示「Demo sign-in successful」toast，清楚說明Preview only。沒有真實身份驗證，不儲存密碼。
4. 共用前台Header：保留品牌；示範登入後以餘額、通知鈴鐺與選單取代Log In／Register。沿用Wallet示範餘額₱13,300.00，點擊進入Wallet。
5. 鈴鐺：未讀提示小點，點擊開啟通知面板，列一則明確標示Sample的歡迎提示；閱讀後清除提示點。
6. 選單：提供My、Wallet及Log Out；登出清除示範登入狀態，恢復訪客header並顯示toast。面板具關閉、Esc與焦點回復。
7. 登入狀態跨前台路由共用；刷新後恢復訪客。註冊與第三方登入維持現有未串接提示。
8. 完成Finish驗收報告；此計畫不包含真實登入、余额或通知API。

## 驗收標準與用例

- 訪客進入任一前台頁：顯示Log In／Register。
- 空白登入：toast與欄位錯誤顯示，保持訪客且不導頁。
- 填入帳號與非空密碼登入：進入首頁，一則示範登入成功toast，header顯示餘額、鈴鐺及選單。
- 跳转Wallet／Affiliate／My：示範登入header一致；餘額與Wallet一致。
- 點鈴鐺：開啟提示，已讀後紅點消失；Esc可關閉並回復焦點。
- 選單登出：訪客header恢復，登出toast顯示；刷新也恢復訪客。
- Toast位於右上角；連續觸發多則時依序往下排列，彼此不覆蓋。各則獨立逾時／手動關閉，剩餘通知補位，不留下舊timer；路由切換不遺失登入提示。
- 320／390／480px與桌面檢查：header不溢出，toast不遮住主要操作；鍵盤及減少動態可用。
- 執行相關登入／導覽測試與npm run build，記錄結果。
